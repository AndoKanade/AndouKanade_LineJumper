### 2.2 各項目の詳細

> 完了した項目（1〜4・7・8）の実装内容は GameClassSpec.md（クラスごとの仕様）と successed.md（日付ごとの実装記録）を参照。

#### 5. ボス戦を作る（未着手）
- 4 で作った敵の仕組みを土台にしたボス戦（専用の攻撃パターン・HP 管理・演出）。
- Enemy の体力・弾の使い回しの仕組みはそのまま流用できる。

#### 6. JSONホットリロード機能（一部対応・優先度低）
- GlobalVariables による調整項目（resource/GlobalVariables/GameScene.json / Title.json）は、実行中の ImGui 編集と外部ファイル書き換えの反映に対応済み。
- レール・的・敵の配置データは各エディターの Save / Load ボタンによる手動操作のため、自動反映は未対応。

### 2.3 次に着手する場合のおすすめ

スタート演出（出発の演出 5 種類・ゲートのカウントダウン・インクで塗る仕組み）は 2026-10-19 に一区切りついた。まず効果音の素材を見つけて `resource/music/se/` に置き、スタート演出の音を入れる。その後はボス戦までの道中を作り込む。おすすめの順番は「スタート台を試し撃ち場にする → レールを伸ばす・チェックポイント → 敵の足場ブロック → 当たったときの演出・サウンド → 5. ボス戦」。

## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **出発までの仮素材**：スタート台の出発ゲートの目印・輪と、操作案内・GO!・カウントダウンの数字の画像は `tools/generate_start_stage_assets.py` で作った仮素材。本番の素材ができたら差し替える。
- **確認用の処理**：Play 中の R キーでタイトルからやり直す処理が、一時的な処理のまま残っている。

### 3.2 コードレビューで見つかった不足点（2026-09-19時点、要優先度調整）

**ゲームシステム**
- スコア・残機・タイマーなどのゲーム状態がない。的の撃破数と連鎖数（ComboCounter）、プレイヤーの体力のみ存在する。
- ポーズ機能がない。
- 当たり判定はモデルの頂点から求めた境界球（Model::BoundingSphere）同士で行っている。プレイヤーは敵弾との判定（境界球と無敵時間）だけで、敵本体や障害物との接触判定は未実装。
- 弾・しぶきがインクを塗れるのはスタート台の上面だけ（移動線分と平面の判定）。他の壁・床やレールを塗る場合は、移動線分とポリゴンの判定が必要になる。

**UI・演出**
- HUD はプレイヤーの体力・壊した的の数・連鎖数のみ（StageHUD）。敵の体力は ImGui のデバッグウィンドウにしか出ていない。
- クリア画面・ゲームオーバー画面は、画面の名前を描いた仮の画像（`tools/generate_result_assets.py` で生成）を出しているだけ。壊した的の数・最大連鎖数などの結果は ImGui ウィンドウでしか表示していない。

**サウンド**
- 鳴らしているのはタイトルの BGM・決定音・ゲートのカウントダウン（3・2・1 と GO!）（StartSequence）と、カタパルトの溜め・発射音（CatapultDeparture）。ほかのスタート演出の効果音（遮断棒・宙返り・着地）、発射音・被弾音・プレイ中の BGM はまだない。素材をユーザーが見つけて置いたら対応する。

**実装品質・パフォーマンス**
- プレイヤーの弾を発射のたびに `make_unique<Obj3D>` して Initialize している（`PlayerBulletManager::Fire`）。敵弾は Enemy 側で使い回しているため、プレイヤーの弾も同様にプーリングしたい。
- Edit 中の曲線の点列（`RailEditor::sampleObjects_`）とインクのしぶき・破片（`InkEffectManager`）は、1 個ずつ別の Obj3D で描いていて描画命令が多い。Play 中のレールの管は 2026-10-24 に 1 本のモデルにまとめて軽くした（`RailEditor::BuildTubes`）ので、重くなったら同じやり方かインスタンシングで描く。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所を示す目印コメント（「ここから追加」「ここまで追加」など）は書かないこと。処理の意図を説明するコメントのみ記述する。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
