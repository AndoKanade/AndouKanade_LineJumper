### 2.2 各項目の詳細

> 完了した項目（1〜4・7・8）の実装内容は GameClassSpec.md（クラスごとの仕様）と successed.md（日付ごとの実装記録）を参照。

#### ステージ1の今の状態（2026-11-09時点）
- レールは Rail 0〜5 の 6 本（`resource/stage/stage1/rail/rail0.json`〜`rail5.json`）。Rail 1〜5 は鍵の的（各 1 つ）を壊すと出る。Rail 4 の螺旋の入り口にチェックポイントが 1 つある。
- 的は 22 個（うち鍵の的 5 個）。敵は置かない方針（`resource/stage/stage1/enemy.json` は空）。ステージ1は的とレールだけで作る。

- 起動から「タイトル → ゲート前で SPACE → カウントダウン → CountdownFlip で出発 → レール走行」まで動くことを、2026-10-30 に Development で起動して確認した（2026-11-09 にスタート台を作り直した後は、まだ起動して確認していない）。

#### 5. ボス戦を作る（未着手）
- 4 で作った敵の仕組みを土台にしたボス戦（専用の攻撃パターン・HP 管理・演出）。
- Enemy の体力・弾の使い回しの仕組みはそのまま流用できる。ステージ 1 のゴールの的（`GoalTarget`。先を並走し、体力 0 で撃破）も土台にできる。

#### 6. JSONホットリロード機能（一部対応・優先度低）
- GlobalVariables による調整項目（resource/GlobalVariables/GameScene.json / Title.json）は、実行中の ImGui 編集と外部ファイル書き換えの反映に対応済み。

#### 9. スタート台の4辺からステージを出す（仕組みは完了）
- スタート台の4つの辺それぞれにゲートを立て、歩いて行った辺のゲートからそのステージへ出発する（スタート台をステージ選択の場所にする）。
- 先に仕組みだけを作り、今のレールをステージ1、残り3つは短い仮のレールにしておく。ステージ2〜4の中身はその後に1つずつ作る。
- 決まったこと（2026-11-09）
  - ゲームが始まったら台の真ん中から始める。
  - 正面の辺がステージ1、右の辺がステージ2、左の辺がステージ3、後ろの辺が最後のステージ（ステージ4）。最後のステージはステージ1〜3をすべてクリアしないと出られない。

  - データはステージごとに分け、エディターは「ステージ → レール → 制御点」の順に選ぶ。
- できたこと（2026-11-09）
  - レール・的・敵のデータを `resource/stage/stage1/` 〜 `stage4/` に分けた（`rail/rail0.json`…・`target.json`・`enemy.json`）。今のデータはステージ1へ移した。

  - スタート台をワールドに固定し、「凸」の形にした（正方形の部分は一辺 16m、後ろの通路は幅 6m・長さ 8m）。正面・右・左の辺と通路の先にゲートを1つずつ立てた。プレイヤーは台の真ん中から始まり、ゲートの前の目印で SPACE を押すと、そのゲートのステージに切り替わって出発する。

  - ステージ1〜3をクリアすると、大ジャンプでスタート台へ戻り、次のステージを選べる。最後のステージをクリアしたときだけクリア画面へ移る。
  - ゴールのレールをレールのデータ（`rail*.json` の `isGoalRail`、Rail Editor の「Goal Rail」）に持たせた。
  - ステージ2〜4に、ゲートの先から外へまっすぐ 40m 伸びる仮のレール（ゴールのレール1本）と、仮の的を4つずつ置いた。
  - Play 中は全ステージのレールを描き、スタート台の上からどのゲートの先のレールも見えるようにした（乗れるのは選んだステージのレールだけ）。
  - ステージ2〜4に出発した後のカメラがレールの正面を向くようにした（ゲートを開けた瞬間に、カメラの基準の向きをそのステージのレールの向きへ付け替える）。
  - クリアしたステージのゲートの前の床をインクで塗るようにした（`StartPlatform::PaintClearedGateFloors()`。台のインクを消すたびに塗り直す）。
  - 後ろの通路に、ステージ1〜3の壁を手前から1枚ずつ立てた（色はステージごとに違う）。立っている壁より奥へは歩けない。最後のステージのゲートは、壁がすべて壊れるまで開けられない。
  - ステージ1〜3をクリアして大ジャンプで着地すると、カメラが通路の壁へ向き、そのステージの壁が壊れてから戻る（`BarrierBreakCutscene`。回す 0.5 秒 → 壊す 1 秒 → 戻す 0.5 秒。調整項目 `barrierTurnDuration` / `barrierBreakDuration` / `barrierReturnDuration`）。SPACE で飛ばせる。
  - プレイ会用の設定を足した（調整項目 `GameScene` グループの `playSessionMode`。初期値は OFF）。ON のときは次のようになる。
    - 開けられるのは正面（ステージ1）のゲートだけ。右・左のゲートの前に来ると「いまは遊べないよ!!」の画像を出す（`StageLockedNotice`、`resource/UI/stageLocked.png`、`tools/generate_stage_locked_notice.py`）。
    - ステージ1をクリアすると、大ジャンプで戻って壁が壊れるのを見せた後に、クリア画面へ移る（その後はタイトルへ戻り、次の人が最初から遊べる）。
    - H キーの操作説明も、画面の流れをステージ1だけにしたもの（`resource/UI/helpPlaySession.png`）を出す。
    - プレイ会では、Global Variables パネルで `playSessionMode` を ON にして Save するか、`resource/GlobalVariables/GameScene.json` の `playSessionMode` を `true` にしたものを使う。提出用は OFF に戻す。
  - 場面ごとに画面の上へ操作の案内を1つずつ出すようにした（仮。`TutorialHints`、画像は `tools/generate_tutorial_hints.py`）。「WASD で移動・マウスで見回す（2m 歩いたら消える）→ 左クリックで試し撃ち（5 発撃ったら消える）→ ゲートの前で SPACE（ゲートを開けたら消える）→ レールで的を撃つ（的を1つ壊すか 6 秒で消える）」の順。タイトルから始め直すと最初から出し、落ちてやり直しても出し直さない。ゴールの的の案内は、見てから足すか決める。
  - 鍵の的を壊して出たレールへ飛び移れるとき、そのレールがある側の画面の端に「A + SPACE」「D + SPACE」を点滅させて出すようにした（`RailSwitchPrompt`、画像は `tools/generate_rail_switch_prompt.py`）。左右は飛び移る処理と同じ判定（`Player::FindSideRailDirection()`）で求める。一度乗った鍵のレールには出さない。最初にこの案内を出したときだけ、飛び移るまで（最大 3 秒）レールを進む・敵・弾・的・しぶきを 0.25 倍の速さにする（カメラとキーの入力は通常の速さ。タイトルから始め直すまでもう一度はしない）。
  - 鍵の的に気づいてもらうため、鍵の的を普通の的の 1.5 倍の大きさにして脈打たせ、最初の鍵の的を壊すまでは近く（35m 以内）の鍵の的の上に「▼」を跳ねさせて出す（画面の外なら画面の端に向きを合わせて出す。`KeyTargetMarker`）。鍵の的が近くにあるときは、操作の案内の続きとして「鍵の的を壊すと となりにレールが出る!」を出す（鍵の的を壊したら消える）。
- 残っていること
  - ステージ2〜4の中身を作る。
  - クリアしたステージの結果（壊した的の数・最大連鎖数）を出していない。
- 未決定：最後のステージをボス戦にするか。台の大きさは仮（`StartPlatform` の `kSquareHalfSize`・`kCorridorHalfWidth`・`kCorridorLength`。変えたら各ステージのレールの始点も合わせて動かす）。
- レールを作るときの注意：各ステージのレールの始点は `StartPlatform::GetRailStartPosition()` の位置に置く（正面 (1.7, 0, 0)、右 (-4.8, 0, -6.5)、左 (-4.8, 0, 6.5)、後ろ (-19.3, 0, 0)。レールは制御点の1番目から始まり、0番目は向きを決めるだけ）。ステージ1は +X、ステージ2は -Z、ステージ3は +Z、最後のステージは -X 方向へ伸ばし、ほかのステージと重ならないようにする。ステージ1の Rail 5 の終点は (201, 1.5, 44) で +Z 側へ寄っている。

## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **仮素材**：PRESS SPACE（`resource/Title/pressSpace.png`）、出発ゲートの目印・輪、操作案内・GO!・カウントダウンの数字（`tools/generate_start_stage_assets.py`）、「STAGE CLEAR!」（`tools/generate_stage_clear_assets.py`）、クリア・ゲームオーバー画面の画像（`tools/generate_result_assets.py`）、落下リスタートの「RETRY」の文字。本番の素材ができたら差し替える。
- **確認用の処理**：Play 中の R キーでタイトルからやり直す処理が、一時的な処理のまま残っている（プレイ会で係の人がやり直すのに使えるため残し、操作説明の画像からは消した）。
- **ステージ2〜4**：まっすぐな仮のレール1本と仮の的4つだけ。

### 3.2 不足点（2026-10-30 にコードと起動で確認、要優先度調整）

**ゲームシステム**
- スコア・タイマーなどのゲーム状態がない。的の撃破数と連鎖数（ComboCounter）、プレイヤーの体力・残機のみ存在する。
- ポーズ機能がない（H キーの操作説明を開いている間だけ止まる）。
- 当たり判定はモデルの頂点から求めた境界球（Model::BoundingSphere）同士で行っている。プレイヤーは敵弾との判定（境界球と無敵時間）だけで、敵本体や障害物との接触判定は未実装。
- 弾・しぶきがインクを塗れるのはスタート台の上面だけ（移動線分と平面の判定）。他の壁・床やレールを塗る場合は、移動線分とポリゴンの判定が必要になる。
- カメラのめり込み防止（`RailCamera::Update()`）は地面の高さとスタート台（`StartPlatform::Raycast()`）だけを見ている。ほかの物を足したら同じように調べる。
- 敵の攻撃は全ての敵で共通のローテーション（単発 → 3方向拡散 → 追尾弾）で、体力以外のパラメータ（移動速度・検知範囲・発射間隔など）は `Enemy.h` の定数固定。

**UI・演出**
- HUD は残機・壊した的の数・連鎖数のみ（StageHUD）。体力は画面の縁のインク（ポストプロセスの DamageInk）で表す。敵の体力は ImGui のデバッグウィンドウにしか出ていない。
- クリア画面・ゲームオーバー画面は、画面の名前を描いた仮の画像（`tools/generate_result_assets.py` で生成）を出しているだけ。壊した的の数・最大連鎖数などの結果は ImGui ウィンドウでしか表示していない。
- ステージ 1 をクリアして大ジャンプでスタート台へ戻ったときも、結果を出していない。9. でクリア済みの辺に印をつけるときに一緒に作る。
- 大ジャンプで着地したとき、プレイヤーの向きが跳んでいた向きからレールの向きへ一瞬で切り替わる。

**サウンド**
- 鳴らしているのはタイトルの BGM・決定音・ゲートのカウントダウン（3・2・1 と GO!）（StartSequence）と、カタパルトの溜め・発射音（CatapultDeparture）。ほかのスタート演出の効果音（遮断棒・宙返り・着地）、発射音・被弾音・プレイ中の BGM はまだない。素材をユーザーが見つけて置いたら対応する（音量は調整項目 `seVolume` / `bgmVolume`）。
- `resource/music/se/` の `cancel.mp3`・`move.mp3`・`catapult_preview.mp3` は、今はどこからも鳴らしていない。

**実装品質・パフォーマンス**
- インクのしぶき・破片（`InkEffectManager`）は、1 個ずつ別の Obj3D で描いていて描画命令が多い。レールの管（Play 中は 2026-10-24、Edit 中の曲線・着地範囲は 2026-10-28）は 1 本のモデルにまとめて軽くした（`RailEditor::AppendTubeMesh`）ので、重くなったら同じやり方かインスタンシングで描く。
- GPU-Based Validation は Debug だけで有効（Development はデバッグレイヤーのみ、Release はどちらもなし）。描画がおかしい・落ちるときは Debug で動かして出力ウィンドウを確認する。
- 使われていない物が残っている：RailEditor の分岐設定（UI と `rail*.json` の `branchTargetRailIndex` / `branchTargetPointIndex`）、`StartSequence::IsIntroRunning()`、`GameScene.json` の `aimSpeed`・`aimYawLimit`・`noseOffset`（どのクラスも登録していない古い項目）。
- ImGui のデバッグウィンドウ名が `"Rail Branch Debug"` のまま（分岐は使っていない）。Play 中も常に出ていて、右側のパネルに重なる。
- 放射ブラーが終わると、ポストエフェクトの種類を Default に戻す（`Application::Update()`）。ImGui で別の種類を選んでいても戻ってしまう。
- Release 構成で動かしての確認はまだしていない（ビルドが通ることだけ確認済み）。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所を示す目印コメント（「ここから追加」「ここまで追加」など）は書かないこと。処理の意図を説明するコメントのみ記述する。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
