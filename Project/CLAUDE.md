#### 5. ボス戦（2026-11-16 に完了。見た目は仮）
- 場所はステージ4。ゲートからのレール（Rail 0）で出発し、終点で輪（Rail 1。中心 (-60, 4, 0)・半径 14 のループするレール）へ自動で飛び移り、輪の中心に浮かぶボス（`Boss`）の周りを回りながら撃つ。
- ボスは2形態。1形態目（体力 120）は、先読みの 3 連射 → 5 方向の扇 → 追尾弾。体力が尽きると2形態目（体力 160）に変わり、内側の輪（Rail 2。半径 9、上下に波打つ）が現れ、輪を回る速さが上がり、プレイヤーが乗っている輪を塗り返す攻撃が加わる（W / S + SPACE で別の輪へ飛び移って避ける）。
- 弾を撃つ前には予備動作（体をふくらませて白く光る）がある。体力は画面の上のゲージ（`BossHpGauge`）と体の色で表す。
- 倒すと、体が震えて弾け、「STAGE CLEAR!」を出してから `StageResult` に結果を書き込み、Clear Transition でクリア画面へ移る。
- 残機を減らしてやり直すときはボスの体力を残し、コンティニューでは残機が尽きたときの形態の最初から戦い直す。
- 数値は調整項目のグループ `Boss`（`resource/GlobalVariables/Boss.json`。Save するとできる）にある。詳しくは GameClassSpec.md の Boss を参照。
- 一緒に作ったもの：ループするレール（Rail Editor の「Loop Rail」）、終点で自動で飛び移るレール（「End Transfer Rail」）、敵の弾の使い回しの共用（`EnemyBulletPool`）、プレイヤーの体力制（最大 100、時間とともに回復）。

#### 6. JSONホットリロード機能（一部対応・優先度低）
- GlobalVariables による調整項目（resource/GlobalVariables/GameScene.json / Title.json）は、実行中の ImGui 編集と外部ファイル書き換えの反映に対応済み。外部ファイルの更新時刻は 0.5 秒ごとに調べる（毎フレーム調べると 1〜2ms かかっていたため。2026-11-18）。
- レール・的・敵の配置データは、NaN・無限大を保存すると JSON に `null` と書かれて次に起動できなくなるため、保存・読み込みのときに座標・向きは 0、レールの速さは 1.0 に置き換える（`Game/Editor/EditorJson.h`。置き換えたら出力ウィンドウに `EditorJson:` と出す）。NaN が入る原因（2026-11-18 にステージ1の最初の的の座標が NaN で保存された）は分かっていない。
- レール・的・敵の配置データは各エディターの Save / Load ボタン（または Save All・Ctrl+S）による手動操作のため、自動反映は未対応。

## 3. 現状の課題（随時更新）

> 実装済みの機能一覧はコードを見れば分かるため省略し、暫定対応・不足点のみ記載する。

### 3.1 暫定対応のまま残っている箇所

- **仮素材**：PRESS SPACE（`resource/Title/pressSpace.png`）、出発ゲートの目印・輪、操作案内・GO!・カウントダウンの数字（`tools/generate_start_stage_assets.py`）、「STAGE CLEAR!」（`tools/generate_stage_clear_assets.py`）、クリア・ゲームオーバー画面の画像（`tools/generate_result_assets.py`）、落下リスタートの「RETRY」の文字、ESC の終了確認メニュー（`QuitConfirmMenu`、`tools/generate_quit_confirm_assets.py`）。本番の素材ができたら差し替える。
- **確認用の処理**：Play 中の R キーでタイトルからやり直す処理が、一時的な処理のまま残っている（プレイ会で係の人がやり直すのに使えるため残し、操作説明の画像からは消した）。
- **ステージ2・3**：まっすぐな仮のレール1本と、仮の的4つ（ステージ3は的なし）とゴールの的だけ。
- **ボス戦の仮素材**：ボスのモデル（球にとげと一つ目。`tools/generate_boss_assets.py`）、「まだ終わらない!!」と輪の飛び移り方の案内（`tools/generate_boss_ui_assets.py`）。体力ゲージは白一色の画像に色を付けているだけ。音は鳴らしていない。
- **ボス戦の数値**：体力・攻撃の間隔・弾の速さ・ダメージなどは、遊んで決めた値ではなく最初に置いた値のまま。
- **サブウェポン（Q）・インクタンクの数値**（2026-11-25）：狙う範囲 25・着くまで 0.6 秒、インクの容量 100・メイン 2・サブ 35・1秒に 50 戻る・使ってから 0.5 秒は戻らない、ゴールの的へのダメージ 1発 1、は相談して決めた最初の値で、遊んで調整していない（調整項目 `homingShotRange` / `homingShotFlightTime` / `homingShotGoalDamage` / `ink*`）。ボス戦は撃ち続ける戦いなので、メインの消費が重すぎないか確かめる。効果音は鳴らしていない。

### 3.2 不足点（2026-10-30 にコードと起動で確認、要優先度調整）

**ゲームシステム**
- スコア・タイマーなどのゲーム状態がない。的の撃破数と連鎖数（ComboCounter）、プレイヤーの体力・残機のみ存在する。
- プレイヤーの体力は最大 100 の連続した値で、最後にダメージを受けてから 3 秒たつと少しずつ戻る。残りは画面の縁のインクでしか見せていないため、あとどれだけ耐えられるかが読みにくいかもしれない（遊んで確かめる）。
- ボスの弾を避ける手段は、レールの上で跳ねる（進みが遅くなる）ことと、2形態目で別の輪へ飛び移ることだけ。輪からボスまでが近く（11m）、避けにくいと感じたら `bulletSpeed`・`telegraphTime`・`attackInterval` で調整する。
- ポーズ機能がない（H キーの操作説明を開いている間だけ止まる）。
- 当たり判定はモデルの頂点から求めた境界球（Model::BoundingSphere）同士で行っている。プレイヤーは敵弾との判定（境界球と無敵時間）だけで、敵本体や障害物との接触判定は未実装。
- 弾・しぶきがインクを塗れるのはスタート台の上面だけ（移動線分と平面の判定）。他の壁・床やレールを塗る場合は、移動線分とポリゴンの判定が必要になる。
- カメラのめり込み防止（`RailCamera::Update()`）は地面の高さとスタート台（`StartPlatform::Raycast()`。台の本体・通路の壁・ゲートの柱・梁・遮断棒）だけを見ている。ほかの物を足したら同じように調べる。
- 敵の攻撃は全ての敵で共通のローテーション（単発 → 3方向拡散 → 追尾弾）で、体力以外のパラメータ（移動速度・検知範囲・発射間隔など）は `Enemy.h` の定数固定。
- 輪に乗っている間は、ゲートからのレール（ループしないレール）を出ていない状態（点線）にしている。輪のすぐ横を通っていて、出したままだと輪から輪へ飛び移るときに一番近いレールとして選ばれ、飛び移れない区間ができるため（`GameScene::ApplyRailLocks()`）。
- ボスの当たり判定は体の球だけで、とげには当たらない。

**UI・演出**
- HUD は残機・壊した的の数・連鎖数のみ（StageHUD）。インクの残りはレティクルの右横のゲージ（InkGauge）で出す。体力は画面の縁のインク（ポストプロセスの DamageInk）で表す。雑魚敵の体力は ImGui のデバッグウィンドウにしか出ていない（ボスの体力は画面の上のゲージに出る）。
- ボスを倒してクリア画面へ移るまでの間、プレイヤーは輪の上で止まり、カメラも動かせない。
- クリア画面は、行ごとにインクのしみを塗ってから全ステージの合計（壊した的の数・最大連鎖数）を数え上げ、最後にランク（S〜C）を押す（`ClearResultUI`、ランクの画像は `tools/generate_clear_rank_assets.ps1`）。ランクは、的を壊した割合（重み 0.7）と、最大連鎖数を満点の連鎖数 10（`kFullComboCount`）で割った割合（重み 0.3）で決める（10 は仮の値）。SPACE で途中を飛ばせる。出し終えてから 0.5 秒（`kReturnInputDelay`）は SPACE でタイトルへ戻れず、「SPACE でタイトルへ」もそこから出す（飛ばした直後の連打で結果を見ないまま戻らないようにする）。効果音は仮の音（`tools/generate_clear_se.py` で作った `resource/music/se/clear_*.wav`）を鳴らしている。本番の音は同じ名前のファイルに置き換える（mp3 などにするときは `ClearResultUI.cpp` のファイル名も変える）。ステージごとの結果はクリアした瞬間に `StageResult` に残し（`GameScene::RecordStageClear()`）、クリア画面へ移る直前に合計する。ほかの案は `docs/ClearSceneIdeas.md` にまとめた。
- ゲームオーバー画面は、画面の名前を描いた仮の画像（`tools/generate_result_assets.py` で生成）と選択肢を出しているだけ。
- ステージ 1 をクリアして大ジャンプでスタート台へ戻ったときも、結果を出していない。9. でクリア済みの辺に印をつけるときに一緒に作る。
- 大ジャンプで着地したとき、プレイヤーの向きが跳んでいた向きからレールの向きへ一瞬で切り替わる。

**サウンド**
- 鳴らしているのはタイトルの BGM・決定音・ゲートのカウントダウン（3・2・1 と GO!）（StartSequence）と、カタパルトの溜め・発射音（CatapultDeparture）、クリア画面のジングル・しみ・数字・ハンコの音（`ClearResultUI`、仮の音）と決定音（ClearScene）。ほかのスタート演出の効果音（遮断棒・宙返り・着地）、発射音・被弾音・プレイ中の BGM はまだない。素材をユーザーが見つけて置いたら対応する（音量は調整項目 `seVolume` / `bgmVolume`）。
- `resource/music/se/` の `catapult_preview.mp3` は、今はどこからも鳴らしていない（`cancel.mp3`・`move.mp3` は ESC の終了確認メニューで鳴らす）。

**実装品質・パフォーマンス**
- インクのしぶき・破片・閃光（`InkEffectManager`）は、GPU で動かして種類ごとに1回の命令で描く（`MeshParticleSystem`、シェーダーは `Engine/Graphics/Shaders/MeshParticle/`。2026-11-24）。出し方（数・速さ・ばらつき）は今までどおり `InkEffectManager` で決める。
  - 種類ごとのモデルは `InkEffectManager.cpp` の先頭の表（パス・大きさを揃える倍率・原点をずらす量）で決める。配布モデルから差し替えるときはそこだけを書き換える。しぶきは飛ぶ向きにモデルの +Z を向けて伸ばす。
  - 見た目を Obj3D と同じにするため、`MeshParticle.PS.hlsl` のライティングは `Object3d.PS.hlsl` と同じ式にしている。Obj3D のライティングを変えたら、こちらも合わせて変える。
  - 台に落ちたしぶきは、GPU で「台の上面の高さを上から下へ横切った」ものを見つけて次のフレームに CPU へ返し、`StartPlatform::TryLandInk()` で塗れたら消す。そのため、塗られるのは今までより1フレーム遅く、その1フレームは台の上面のすぐ下にいる（ほとんど台に隠れる）。調べられるのは水平な面1枚だけ。
  - レールの管（Play 中は 2026-10-24、Edit 中の曲線・着地範囲は 2026-10-28）は 1 本のモデルにまとめて軽くした（`RailEditor::AppendTubeMesh`）。
- GPU-Based Validation は Debug だけで有効（Development はデバッグレイヤーのみ、Release はどちらもなし）。描画がおかしい・落ちるときは Debug で動かして出力ウィンドウを確認する。
  - Development は実行ライブラリにデバッグ版（`/MTd`）を使うため、コンパイラーが `_DEBUG` を自動で定義する。Debug だけで動かす処理は `#ifdef _DEBUG` ではなく `#if defined(_DEBUG) && !defined(DEVELOPMENT_BUILD)` で分ける（`DEVELOPMENT_BUILD` は Development だけで定義している）。
  - 2026-11-18 まで、これに気づかず Development でも GPU-Based Validation が有効になっていて、全体が 35〜50 FPS に落ち、初めて使うシェーダー（インクを塗る・火花・ポストエフェクト）で 150〜230ms 止まっていた。直した後はステージ4のボス戦まで約 55 FPS で、初めて使ったときの止まりも出ない。
- パーティクルは `MeshParticleSystem` の1つだけ（2026-11-24 に `ParticleManager`・`ParticleEmitter`・`Shaders/Particle/` を消した）。被弾の火花も `InkEffectManager` の種類の1つ（`EmitSpark`。Player・GoalTarget・Boss・EnemyManager は `SetInkEffect()` で GameScene の `InkEffectManager` を借りる）。種類は最大 5（`kMaxKinds`。`MeshParticle.hlsli` と合わせる）で、今は5つとも使っている（しぶき・破片・閃光・火花・ボスの予備動作の光の粒）。
  - 火花は、前の板ポリゴン＋加算合成から、球のモデル＋通常の半透明の合成（ライティングなし）に変わった。値（`InkEffectManager.h` の `kSpark*`）は前と同じで、遊んで決めた値ではない。
- シーンが切り替わったときの読み込みで 0.4〜0.6 秒止まる（ゲームへ戻ったときは、レールの管を作る 40ms も入る）。暗転の演出の裏で起きていれば問題ない。
- ウィンドウのメッセージの処理（`WinAPI::ProcessMessage()`）が、ときどき 10〜28ms かかる（1 フレーム遅れる程度）。霧のタイル（`Ground::DrawFog()`）は 1 枚ずつ描いていて、重いフレームでは 5〜12ms かかる。
- 使われていない物が残っている：RailEditor の分岐設定（UI と `rail*.json` の `branchTargetRailIndex` / `branchTargetPointIndex`）、`StartSequence::IsIntroRunning()`、`GameScene.json` の `aimSpeed`・`aimYawLimit`・`noseOffset`（どのクラスも登録していない古い項目）。
- ImGui のデバッグウィンドウ名が `"Rail Branch Debug"` のまま（分岐は使っていない）。Play 中も常に出ていて、右側のパネルに重なる。
- 放射ブラーが終わると、ポストエフェクトの種類を Default に戻す（`RadialBlurPostEffectState::Update()`）。ImGui で別の種類を選んでいても戻ってしまう。
- 使わなくなった調整項目は無いが、`GameScene.json` を Save すると、今回足した項目（`playerMaxHp`・`hpRegenStartDelay`・`hpRegenSpeed`・`enemyBulletDamage`）が書き足される。
- Release 構成で動かしての確認はまだしていない（ビルドが通ることだけ確認済み）。2026-11-16 のボス戦は Debug でビルドし、Development で起動して確認した。

## 4. 開発ルール

### 4.1 コーディング規約

- **命名規則・インデント**：一般的な C++ の規約に準拠すること。
- **コメントアウト**：処理の意図や内容をなるべく細かく具体的に記述すること。

### 4.2 実装時の禁止事項

- マジックナンバーの使用を禁止する。必ず定数（constexpr 等）を使用すること。
- 無駄な処理を何度も繰り返すような、非効率なコーディングをしないこと。

### 4.3 AIへの指示（厳守事項）

- 回答は短く簡潔にすること。
- 聞かれたこと以外の余計なコードを追加しないこと。
- コードの順番を勝手に変更しないこと。
- 変更箇所を示す目印コメント（「ここから追加」「ここまで追加」など）は書かないこと。処理の意図を説明するコメントのみ記述する。
- コメントアウトに不自然な記号を使用しないこと。
- 提示されたコードを省略して返すのは禁止。
- 「整理して」と指示された場合は、処理内容は一切変更せず、不要なコメントの削除・わかりやすいコメントの追加・インデントの改善のみ行うこと（見やすさのための順番変更は許可する）。
